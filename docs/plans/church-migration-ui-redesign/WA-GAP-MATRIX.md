# WhatsApp-Fidelity Gap Matrix (flag-on / `whatsapp-shell`)

Audit date: 2026-07-29. Method: read the current flag-on Chats tab screenshot
(`IMG_1243`) against a WhatsApp-iOS reference (`IMG_1223`), then read the code
of every flag-on surface to check styling approach vs WhatsApp anatomy. A
surface is "untouched" when it has **zero** `whatsappShellEnabled` /
`useWhatsappShell` references — meaning it renders identically regardless of
the flag, i.e. no restyle work has started there at all.

Legend — Scope: **S** = a few hours (tokens/props only), **M** = one focused
PR (new sub-components, no data changes), **L** = multi-day (new
architecture: wallpaper layer, bubble rewrite, composer rewrite).

## 5 biggest gaps overall

1. **The chat room (`ConvexChatRoomScreen.tsx`, `MessageItem.tsx`, `MessageInput.tsx`, and the group `ChatHeader`) has literally zero `whatsappShellEnabled` references.** It is the single largest, most-used flag-on surface and has not been touched — no wallpaper, iMessage-shaped bubbles/tails instead of WhatsApp's, a bordered-box composer instead of a rounded pill, and no brand-color usage anywhere in the room.
2. **No wallpaper token or layer exists anywhere in the theme system** (`theme/colors.ts` has no `wallpaper`/`chatBackground` key) — the chat room renders on a flat `colors.surface`, which is the most visually obvious "not WhatsApp" signal a user would notice.
3. **Brand color does not reach the two places WhatsApp shows its accent color most: own-message bubbles and the composer send button.** `chatBubbleOwn` is a static per-theme token (iMessage blue in light mode, hardcoded WhatsApp green in dark mode — backwards, since it should be *brand* color in both, not literal WA green), and the composer's `+`/send icons use `themeColors.link` (fixed iOS blue) instead of `useCommunityTheme().primaryColor`. This directly undermines the "WhatsApp Plus" goal of brand color substituting for green.
4. **The Chats list is restyled inconsistently even within itself:** `GroupedInboxItem.tsx` got a real flat `waRow` treatment (avatar/title/preview/right-column/hairlines), but the four other row kinds rendered by `ChatInboxScreen.tsx` directly — DM rows, the synthetic Notifications row, ghost/"coming soon" rows, and event rows — were left on their pre-restyle bespoke layouts (different avatar size, no timestamp on DM rows, accent-bar-and-pill event cards). A user scrolling the real inbox sees two different row languages interleaved.
5. **Five whole surfaces are completely untouched by the flag** (zero `whatsappShellEnabled`/`useWhatsappShell` references): `ConvexChatRoomScreen.tsx`/`MessageItem.tsx`/`MessageInput.tsx` (chat room, see #1), `CommunityPageScreen.tsx` (new screen, incidentally close already), `GroupInfoScreen.tsx`, `InviteKitScreen.tsx`, and `inbox/new.tsx`. Most critically, **`ProfileScreen.tsx` (the "You" tab) still hardcodes the header text "Profile"** — even the title-only change the task brief expected hasn't actually landed in the screen itself, only in the tab bar label.

## Recommended PR sequencing

**Foundation kit first — everything else blocks on this:**

- **PR 1 — Theme tokens** (`theme/colors.ts`, `useCommunityTheme.ts`): add `wallpaper`/`chatBackground`, a `groupedBackground` distinct from `surface`, and brand-derived bubble/composer helpers (e.g. `useCommunityTheme()` returning `bubbleOwnBackground`/`bubbleOwnText` computed from `primaryColor`, replacing the static `chatBubbleOwn` token). No visual surfaces change yet — this is pure plumbing. **Do this before any bubble/composer/wallpaper work**, or those PRs will churn re-doing token names.
- **PR 2 — Shared row kit extraction**: pull `waRow` / `WaRightColumn` / `WaSeparator` / `WaChannelIcon` out of `GroupedInboxItem.tsx` into a shared component (e.g. `components/ui/WaRow.tsx`), keeping `GroupedInboxItem` as the first consumer. This unblocks surfaces #2, #14, #16 from reinventing the row shape.

**Then parallelize — grouped by file-conflict potential (agents in the same group touch disjoint files and can run concurrently; groups are ordered by rough priority, not a hard sequence):**

- **Group A — Chat room rebuild (highest priority, largest, mostly self-contained files)**
  - Agent: wallpaper layer + `ConvexChatRoomScreen.tsx` background/day-pills (depends on PR 1).
  - Agent: `MessageItem.tsx` bubble shape/color/tail/timestamp rewrite (depends on PR 1; sequence *after* the wallpaper agent lands so bubble contrast is checked against the real background, or coordinate a shared branch).
  - Agent: `MessageInput.tsx` composer pill + brand-colored send/attach icons (depends on PR 1; independent of the other two files, safe to run in parallel with them).
  - Agent: `ChatRoomHeader.tsx` + the group `ChatHeader` (not yet located/read — locate first) polish pass — independent file, safe in parallel.

- **Group B — Chats list row consistency (depends on PR 2)**
  - Agent: convert `DirectMessageRow` + `NotificationsInboxRow` to the shared row kit (add the missing timestamp, fix avatar size) — file: `ChatInboxScreen.tsx`.
  - Agent: convert `GhostChannelCard` to the shared row kit — same file as above, **so these two agents must NOT run concurrently** (both edit `ChatInboxScreen.tsx`); sequence them, or split by function boundary and merge carefully.
  - Agent: `EventInboxRowItem` redesign (drop accent bar/urgency pill/inline CTA in favor of flat row + minimal urgency signal) — same file, same conflict risk as above; run after the other two `ChatInboxScreen.tsx` agents, not concurrently.

- **Group C — Secondary/settings-style surfaces (fully independent files, safe to run all at once)**
  - Agent: `ProfileScreen.tsx` + `ProfileHeader.tsx` (fix the "Profile"→"You" header text bug first, then full row-kit pass on `ProfileMenu.tsx`).
  - Agent: `GroupInfoScreen.tsx` corner-radius/spacing consistency pass.
  - Agent: `ChannelInfoScreen.tsx` + `app/inbox/[groupId]/channels.tsx` consistency pass.
  - Agent: `InviteKitScreen.tsx` card→flat-row pass (or explicit decision it stays card-styled).
  - Agent: `inbox/new.tsx` people-picker row pass (adopt shared row kit from PR 2).
  - Agent: `CommunityPageScreen.tsx` nav-bar-over-brand-band + section-header casing polish (lowest priority — already closest to WA).

- **Not yet scoped — read before assigning:** the events tab screen (`app/(tabs)/events.tsx`) was not opened this pass; give it its own read-and-scope pass before folding it into Group C.

Rationale for the grouping: Group A and Group B touch entirely disjoint files
from each other and from Group C, so those two groups can run fully in
parallel once PR 1/PR 2 land. Within Group B, all three agents edit the same
2300-line `ChatInboxScreen.tsx`, so they must be sequenced (or given
tightly-scoped diff regions) to avoid merge conflicts — this is the one place
in the whole plan where "parallelize" would actually collide.
